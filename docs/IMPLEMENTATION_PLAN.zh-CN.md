# 实施主计划：动态 YOLO 分类与摄像头网页

更新：2026-10-04。本文是项目唯一的技术主线。旧的
[四周团队计划](PROJECT_PLAN_4_WEEK.md)仅保留课程日期与提交要求；
其中时序模型消融等研究任务不决定当前产品实现顺序。每一步达到验收条件再进入下一步。

## 目标与当前状态

最终使用方式：用户将外置摄像头接到运行电脑，在网页选择摄像头并开始洗手；
YOLO 图像分类器对连续送入的画面逐帧分类。页面显示实时画面、当前动作、
六步进度和结束后的完整性报告。模型在云端机器完成训练，部署电脑只负责推理。
第一版按单人、单摄像头、本机网页设计。

当前仓库已有数据准备、训练、评估、视频文件推理和六步完整性报告的命令行流程。
实时推理接口及本机摄像头网页也已有代码入口。正式清洗数据、云端训练结果、
真实摄像头上的分类效果和延迟尚未验收；页面不能替代模型实测。
GitHub 仓库附带当前云端训练选出的七类帧模型 `exp.pt` 及其 GRU 时序头
`exp_temporal_head.pt`，可用 `python scripts/run_camera.py --demo-exp` 体验分类、
时间线与完整性报告；加 `--no-temporal-head` 可回退至纯帧模型作对照。
该权重可以用于阶段展示和固定数据版本上的离线评估；最终报告仍须分别给出
独立测试集、跨场景数据和手机摄像头实测，不能将三者混为同一个准确率。

开题或阶段展示可以在网页中载入一段**公开数据或受控录制的本地验证视频**，以稳定展示
“逐帧分类→进度→完整性报告”的完整链路。页面会明确标注这是离线验证输入；它不能替代
独立手机摄像头上的实时泛化测试，也不得把该结果写成实时部署性能。

技术主线：

    原始视频/标注 → 清洗与人工抽查 → 冻结训练/验证/测试集
                  → 云端训练 YOLO 逐帧分类 → 下载模型及配置
                  → 本地视频推理验收 → 外接摄像头逐帧送图
                  → 过去帧概率平均 → 网页显示与六步报告 → 真实场景验收

截至 2026-10-04 已完成的阶段性增强：PSKUS 训练准备加入双标注一致过滤与动作切换边界帧
剔除；本地页面支持受控视频演示；`data/external/pskus_demo_validation/` 保存 5 条正确流程和
3 条错误流程的公开标注验证视频。它们用于定性展示，不能替代独立测试集或手机摄像头的泛化结论。

## 第 1 步：固定数据与演示口径

- [ ] 确认正式训练数据来源、使用权限、原视频和标注文件的完整清单。
- [ ] 固定六步及其他动作的标签映射；明确无法辨认的画面如何处理，不擅自标成某一步。
- [ ] 固定最终评估指标：逐类召回、Macro-F1、混淆矩阵，以及漏步、乱序、过短判断。
- [ ] 固定演示设备：外置摄像头类型、部署电脑和可接受的推理延迟。实时演示只使用已到达的帧。

**交付物：**数据清单、标签说明、目标设备记录、评估口径。
**完成标准：**所有后续实验使用同一标签顺序和同一评估定义。

## 第 2 步：清洗并冻结高质量数据集

- [ ] 使用现有 prepare 流程按原始视频分组划分，再抽帧并生成 manifest。
- [ ] 核查视频损坏、重复/近重复、标签缺失、时间戳错位、帧与标注不一致。
- [ ] 按动作类别、拍摄角度和动作切换边界抽样人工复核；记录修订和剔除原因。
- [ ] 统计每类、每个 split 的视频数和帧数；检查同一原视频、同一参与者
      （若身份可得）及重复片段没有跨越训练和最终测试集。
- [ ] 冻结数据版本；测试集留到选模完成后使用，不能据其结果反复调整模型。

**交付物：**版本化 manifest、清洗记录、样本抽查表、数据集统计与划分报告。
**完成标准：**人工抽查通过、标签/时间对齐可追溯、无已知跨 split 泄漏；
每个保留类别的样本量和限制写入数据说明。

## 第 3 步：在云端跑通可复现训练

- [ ] 将本项目代码、冻结的数据版本和配置部署到云端训练机；记录依赖版本及设备。
- [ ] 先运行环境检查和小规模训练，确认数据读取、标签通道、损失和 checkpoint 正常。
- [ ] 使用 configs/experiments/live_yolo_frame.yaml 训练 YOLO 逐帧分类模型；
      云端 CUDA 可覆盖 runtime.device=cuda 与 train.precision=fp16。
- [ ] 每次实验记录配置哈希、数据版本、随机种子、验证集指标、权重来源和输出目录。
- [ ] 根据验证集 Macro-F1、逐类召回、动作切换稳定性及推理耗时选择正式权重。
      实时显示仅平均已到达帧的概率，不依赖未来画面。

**交付物：**训练记录、验证结果、选模理由和云端最佳 checkpoint。
**完成标准：**能从记录复现结果；正式权重来自验证集选模，而非最后一轮或测试集挑选。

## 第 4 步：打包模型并验证本地视频推理

- [ ] 从云端取回最佳权重、最终配置、标签顺序、图像预处理、采样率、
      依赖版本及模型版本号。
- [ ] 在部署电脑加载权重，用现有 infer 和 assess 流程处理几段真实视频。
- [ ] 核查逐帧类别、时间戳、六步报告和人工观察；与云端相同输入的输出对照。
- [ ] 在锁定的测试集和独立拍摄视频上报告最终指标与典型失败场景。

**交付物：**可迁移的模型包、离线视频样例输出、最终评估表。
**完成标准：**部署电脑稳定加载模型；预处理和类别顺序正确；视频推理与完整性报告可复现。

## 第 5 步：实现实时推理服务

- [x] Python 后端已有开始、送帧、停止接口；会话维护时间戳与逐帧预测。
- [x] 已复用训练时的图像预处理；实时分类只读取当前帧，展示平滑只读取过去帧。
- [x] 网页同一时间最多发送一帧，推理赶不上时跳过待发送的旧画面。
- [x] 网页接收当前步骤、置信度和六步进度；结束时复用项目完整性判定规则。
- [ ] 用正式 YOLO checkpoint 核对类别映射、时间轴与报告输出。
- [ ] 记录目标设备上的吞吐、端到端延迟和内存占用，按实测结果调整采样率与批量。

**交付物：**实时推理接口及本地服务启动方式。
**完成标准：**持续输入时结果不断更新、时间顺序正确、停止后报告与保存的逐帧结果一致。

## 第 6 步：实现外置摄像头网页

- [x] 页面列出可用摄像头，支持选择外置摄像头、权限申请和实时预览。
- [x] 页面提供开始、停止、重新开始，显示当前步骤、六步进度和最终报告。
- [x] 页面将采样画面及采集时间送至本地后端，显示断线或推理错误。
- [x] 页面标明实时进度为暂定结果，结束后展示完整会话判定。
- [ ] 在目标浏览器、外接摄像头和正式模型上完成实际操作验收。

**交付物：**能在目标电脑浏览器打开的前端页面。
**完成标准：**无需命令行操作即可选摄像头、完成一次洗手演示并看到结果。

## 第 7 步：真实场景验收与交付

- [ ] 用真实外置摄像头录制正确流程、漏步、乱序、过短，以及遮挡/光照变化场景；
      对照人工答案，记录成功与失败案例。
- [ ] 核查启动、停止、重复使用、摄像头断开和长时间运行；记录实际延迟，
      给出在目标电脑上可接受的延迟阈值及测量结果。
- [ ] 固定模型版本和阈值；在另一台干净电脑按文档安装、接摄像头并演示。
- [ ] 整理代码、模型包、数据说明、指标、局限、演示视频和课程提交材料。

**交付物：**验收记录、可复现安装说明、最终系统与报告。
**完成标准：**陌生人按说明可完成一次摄像头演示；性能数字对应固定的数据与模型版本。

## 当前执行顺序

从第 1 步开始，依次通过数据质量、云端训练、本地视频推理三个关口，
再在真实摄像头上验收实时服务与页面。当前页面入口：

    python scripts/run_camera.py config=configs/experiments/live_yolo_frame.yaml --checkpoint path/to/best.pt

本机浏览器打开 http://127.0.0.1:8765/。权重必须与该配置的模型架构、
标签顺序和预处理一致；早期可行性测试的模型与数据文件不作为默认输入。

GRU/TCN 与 [PE 等旧研究方案](zh/MODEL_FRAMEWORK.md)不属于当前主线。
