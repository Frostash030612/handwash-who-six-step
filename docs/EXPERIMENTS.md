运行：`python scripts/audit_demo.py --folder data/external/pskus_demo_validation`。
两种方法使用同一份 `exp.pt`、同一批 5 fps 采样帧；GRU 另加载与该权重绑定的
`exp_temporal_head.pt`。逐段数据在 `outputs/exp_demo/demo_audit/summary.csv`，
`metadata.json` 记录配置与权重 SHA-256；逐段 JSON/Markdown 报告在对应视频子目录。

| 观察项 | 逐帧＋过去 9 帧概率平均 | GRU |
| --- | ---: | ---: |
| “正确流程”组 5 段：六步齐全且无逆序 | 2/5 | 4/5 |
| “错误流程”组 3 段：至少报出漏步 | 3/3 | 3/3 |
| “正确流程”组：系统报总搓洗不足 40 秒 | 3/5 | 4/5 |

需要人工复核的具体案例：`2020-06-30_04-38-38_camera102.mp4` 在 GRU 下仍被报乱序；
`2020-06-27_21-22-07_camera102.mp4` 的 GRU 综合分为 99.52%，同时出现单步时长不足警告。
前端现已根据警告显示黄色结论，避免只看高分误以为没有问题。错误组中的
`2020-06-28_02-46-35_camera104.mp4` 在 GRU 下未检出任何 WHO 步骤；此时“没有逆序”
不等于“顺序正确”，前端显示为证据不足。当前规则仍会因为 `is_in_order=true` 给这段
零检出视频 0.30 综合分；这是评分口径的待解决问题，正式报告不能把该分数解释为质量达标。

这 8 段只带“正确/错误”目录名，本地缺少可核对的逐段人工步骤和时长标注，
也未确认是否与 `exp.pt` 的训练/选模视频互斥。上表是失败案例筛查，
不能写成独立测试准确率、漏步 precision/recall 或摄像头实时性能。

## 动作切换平滑算法（2026-10-11，DataSet1/3/4）

`scripts/evaluate_yolo_full_videos.py` 现在同时比较两种离线后处理：

- `mean_min_run`：对相邻类别概率取中心滑动平均，再合并过短的孤立类别段。
- `hysteresis`：新动作必须连续出现若干窗口，且相对当前动作有足够概率优势才确认切换；确认后把分界回填到候选动作首次出现处。

参数只在原视频级验证集挑选，并额外记录切换附近的 Accuracy / Macro-F1；选好后再固定参数评估测试集。该方法不强制 WHO 六步顺序，避免把真实错序预测“修正”成正确顺序。回填边界使用后续帧，因此是离线算法；实时摄像头需实现只看过去帧的版本并单独报告确认延迟。

本轮 263 段视频按原视频划分，测试集 40 段、1,895 个一致标注窗口中心。验证集选中 `hysteresis`：概率平均宽度 3、连续确认 3 个采样帧（5 fps）、margin=0、min_run=1。固定参数后的测试集结果：

| 后处理 | Accuracy | Macro-F1 | 切换附近 Accuracy | 切换附近 Macro-F1 |
| --- | ---: | ---: | ---: | ---: |
| 未平滑 | 0.8850 | 0.6914 | 0.7053 | 0.6499 |
| 验证集选定滞回 | 0.9008 | 0.7181 | 0.7351 | 0.6945 |

这是 YOLO26m-cls 的整段视频分类结果，说明滞回后处理在该测试划分上减少了抖动；不是完整六步合规率，也不能直接外推到实时摄像头或其他场景。待 VideoMAE 修复版完成后，应使用同样的后处理规则和视频划分进行对照。

### PSKUS DataSet1/3/4 云端试训状态（2026-10-11）

- YOLO26m-cls 从 `exp.pt` 微调，最多 30 轮、patience=5；按原视频隔离的帧级测试 Top-1 为 0.907、Top-5 为 0.999。它是试训指标，不等于整段视频或六步合规准确率。
- 使用同一 YOLO26m-cls 权重跑 40 段完整测试视频、1,895 个双标注一致中心点；验证集选定的滞回后处理把测试 Macro-F1 从 0.6914 提至 0.7181，切换附近 Macro-F1 从 0.6499 提至 0.6945。结果在 `outputs/pskuss_ds134_yolo_video_test/`。
- VideoMAE 的 FP16 首次试训在第 3 轮解冻主干后出现 NaN，已停止并保留失败产物。修复版使用 BF16、主干学习率 `1e-6`、分类头学习率 `1e-5`，单独写入 `outputs/pskuss_ds134_videomae_stable/`；以第 2 轮最佳权重测试，1,235 个稳定窗口的 Accuracy 为 0.9749、Macro-F1 为 0.8762。某些动作类测试窗口仅 6～24 个，不能将该数字解释为稳健的全视频合规率。
- 上述只使用 DataSet1/3/4，不能称为 11 个 PSKUS 分片的全量训练。DataSet2 已完成传输，但这版试训未纳入它。

### DataSet2 加入 YOLO 与 VideoMAE 的增量实验（2026-10-11，已完成训练）

- 云端 `DataSet2.zip` 已通过公开来源 MD5 校验并解压；本实验把 DataSet1/2/3/4 一起构建为七类 Ultralytics 分类数据。沿用双标注一致和动作边界前后 7 原始帧过滤；仅训练集对 `other` 做 1:1 上限抽样。
- 使用 `data/processed/pskuss_ds134_yolo/video_splits.csv` 锁定旧视频的 train/val/test 归属，DataSet2 新视频再单独按哈希划分。这样从 DataSet1/3/4 的 `best.pt` 继续微调时，旧验证/测试视频不会进入新训练集。
- 已构建 `data/processed/pskuss_ds1234_yolo/`：615 段双标注视频（train 430、val 92、test 93），共 93,118 张合格图像；新增 DataSet2 352 段，旧 263 段视频的划分和标注员配对逐项核对，变化为 0。YOLO 从 `outputs/pskuss_ds134_yolo/weights/best.pt` 微调完成，稳定帧测试 Top-1 为 0.9581、Top-5 为 0.9995；这不是完整视频成绩，也不是 11 分片全量训练。
- VideoMAE 使用同一 615 段视频划分，16 帧窗口、双人一致和前后 7 原始帧稳定规则。旧构造检查得到 22,378 个稳定窗口；其中 1 段视频因双标注时间轴不齐而没有可用窗口。仅将训练集 `other` 按确定性哈希限制到与六步动作总数相同的数量，验证/测试不抽样，最终使用 11,223 个窗口。以 1/3/4 修复版权重为起点，最佳 epoch 8，稳定窗口测试 Accuracy 0.9819、Macro-F1 0.9249（3637 个测试窗口）。该指标不能代替完整视频指标。
- 为避免重新计算划分造成泄漏，整段视频对照严格读取训练时的 `video_splits.csv`。在 93 段原视频的 5599 个双标注一致中心点上，验证集选定平滑后 YOLO 基线 Macro-F1 为 0.9025、原 VideoMAE 为 0.7721、改进 VideoMAE 为 0.8745、当前 YOLO 权重绑定的新 GRU 为 0.9271。切换附近 Macro-F1 依次为 0.8327、0.5842、0.7944、0.9006。改进 VideoMAE 与 GRU 均已训练和评估完成，详细协议、配对区间和权重指纹见 [公平整段视频对照](FAIR_VIDEO_COMPARISON.zh-CN.md)。

## 消融实验设计（E3，对应研究问题 3）

固定数据、划分、seed 和骨干：A/B 只比较后处理；C/D 比较两种时序模型。

| 组 | `model.temporal.kind` | `train.mode` | `infer.temporal_apply` | 回答的问题 |
| --- | --- | --- | --- | --- |
| A | none | frame | false | 纯逐帧基线 |
| B | none | frame | true | 同一 A checkpoint，只增加概率平滑 |
| C | mean_pool | clip | false | 逐帧特征与过去均值融合 |
| D | gru（或 tcn） | clip | false | 可学习的时序模型 |

A/B 复用同一个 checkpoint；C/D 分别训练。评估时保持相同的 test split，并使用各自
checkpoint 对应的 `model.temporal.kind`、`train.mode` 和 `infer.mode` 配置。

报告里除 Accuracy / Macro-F1 外，**必须给出"帧级跳变次数"或"分段数"**——
否则无法直接说明"时序处理减少了单帧误判"。建议统计：

```
跳变次数 = 平滑前后 标签序列中相邻帧标签变化的次数
```

（可用 `handwash evaluate --splits test` 产出的 `predictions_*.jsonl` 计算并画图。）
