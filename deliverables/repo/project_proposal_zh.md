## 背景 / 目标 / 具体目标

**背景.** 手卫生是预防医疗相关感染最有效的单一措施，但依从性长期偏低，而且极难测量。世界卫生组织（WHO）定义了标准的六步洗手法，并建议整套流程持续 40—60 秒；然而一个人是否真的做完六步、顺序是否正确、时间是否充分，很难靠人工观察在大规模场景下可靠判断：这需要持续注意力，而且已知观察者会系统性地高估依从性。与此同时，视频采集极其廉价且普及——一部手机就够了。本项目把视频视为**视觉传感器流**，构建一个模式识别系统，把它转换为客观的规范性评估结果。

**总目标.** 设计、实现并评估一个可运行的模式识别系统：输入一段洗手视频，(i) 将每一帧的手部动作分类到 WHO 六步中的某一步；(ii) 把该逐帧序列转换为关于**流程完整性**的可核查判定——检出漏步、顺序异常与时长不足的步骤。

**具体目标（可度量）.**

| # | 目标 | 成功标准 |
| --- | --- | --- |
| O1 | 帧级六类动作识别 | 在以视频为单位互斥划分的留出测试集上 Macro-F1 ≥ 0.80 |
| O2 | 时序整合以抑制单帧误判 | 标签跳变次数下降 ≥ 25%，且 Macro-F1 不下降 |
| O3 | 跨场景泛化 | 量化并报告从医院数据迁移到实验室数据时的 Macro-F1 下降幅度 |
| O4 | 流程完整性判定 | 对自采片段，“完整/不完整”与“顺序正确/异常”两项判定与人工真值一致率 ≥ 80% |
| O5 | 可运行系统 | 一条命令完成安装与演示，并在从未见过本仓库的机器上验证通过 |

**范围边界.** 本系统只做**流程规范性分析**：不诊断疾病、不评估微生物学灭菌效果、不替代感染控制专业人员。它评估的是**操作技术**，而不是**临床结果**。

## 项目描述

### 1. 问题定义

摄像机对准一个洗手池。任务是对每一帧输出正在执行的是 WHO 哪一步，并对整段流程输出结构化判定。以下三个难点使它成为一个真正的模式识别问题，而不是简单的分类练习。

(1) 类间视觉相似。第 2 步与第 4 步都涉及手背；第 5、6 步是拇指与指尖的小幅旋转动作。在常见拍摄距离下，它们的差别只有几厘米的手部构型。

(2) 类内差异巨大。同一步动作在不同人、不同机位、不同光照与背景下表现差异明显；当部署环境与训练环境不同时性能会下降——这是典型的域偏移问题。

(3) 时序结构本身是答案的一部分。单帧误判在**流程**层面并不构成错误，只有持续的、有时序关系的行为才是。因此逐帧准确率是不充分的指标，这正是引入时序层的动机。

### 2. 官方要求的四项能力（四项全做，保证三项）

官方要求在四项能力中至少开发、集成并演示三项。本项目覆盖全部四项，并在此明确写出，使贡献不含糊。

| 能力 | 如何实现 |
| --- | --- |
| A1 有监督 / 无监督学习 | **有监督**多分类，使用逐帧真值标签。学习协议采用严格的**视频互斥**训练/验证/测试划分（同一原始视频的帧不得出现在两个划分中）——我们把这一设计视为正确性要求，而不是实现细节。 |
| A2 机器学习 / 深度学习 | **深度学习 + 迁移学习**。主模型：从预训练权重微调的 YOLO 分类网络。基线：MobileNetV2 与另一个 YOLO 分类变体，使任何性能提升都是与同条件参照模型的对比结果。 |
| A3 混合机器学习 / 集成方法 | **两阶段混合架构 + 集成融合**。帧级分类器输出逐帧类别后验；时序模型（GRU 与 TCN 均实现并对比）以帧级嵌入为输入，在有上下文的情况下重新预测。两者在概率层（加权融合）与决策层（多数投票、滑窗平滑）融合。同时实现 mean-pooling 头作为“不做时序建模”的对照，从而把集成的贡献单独隔离出来。 |
| A4 智能感知 / 意义建构 | **在视频传感器流上做意义建构**。系统不停留在标签：它把标签流切分为动作片段、重建实际执行的步骤序列，并施加由 WHO 指南导出的显式领域规则，产出人类可读的规范性报告（各步时长、占搓洗总时长比例、漏步、顺序逆序、时长不足的步骤、综合得分）。 |

### 3. 系统架构

采用五层设计，每层单一职责，依赖只向下指。该结构已在仓库中以唯一来源的方式固定下来（配置契约 + 目录约定），其中契约层、数据与 IO 层、编排层已实现并纳入版本管理，模型层按同一契约在项目第 2—3 周实现。

L0 基础设施——路径常量、日志、异常体系。L1 契约层——标签空间（WHO 六步的唯一权威定义）、数据契约、配置 schema、指标、完整性判定规则。L2 数据与 IO——视频解码、抽帧、带完整性不变量的 manifest、视频互斥划分。L3 模型——帧级分类器（YOLO、MobileNetV2）、时序头（GRU、TCN、mean-pool）、checkpoint 管理。L4 编排——五个流程（prepare、train、evaluate、infer、assess）与命令行入口。

有两个设计决定直接影响评估结论的可信度。第一，**唯一的权威标签空间**：各数据集的原始标签名并不相同（Step 5、step_5、Step5_water 等），它们只在**一处**被映射为规范名，因此训练标签与评估标签不可能悄悄错位——这类故障会产出看起来合理但毫无意义的指标。第二，**视频互斥划分由代码强制**：按帧划分会让近乎相同的相邻帧同时进入训练集与测试集，从而虚高准确率；因此设置三道相互独立的校验，一旦原始视频跨划分就直接终止运行。

### 4. 数据

**PSKUS**（医院环境，逐帧标注）作为主训练数据与同场景测试数据；先取 300—500 段视频的子集打通并验证流水线，再逐步扩大规模。**METC**（实验室环境，72 名参与者，帧级标签）仅用于跨场景测试，绝不用于训练——这正是迁移测量有意义的前提。**Kaggle 洗手数据集**规模小、获取快，用于快速原型与流水线验证。最后，每位组员自采 4—6 段视频用于完整性验证：该集合按脚本设计，包含一套完整正确的流程、一段漏步、一段两步换序、以及一段某步时间过短，每段都配有人工标注的真值序列。自采数据是刻意安排的——它是唯一能在系统所声称的适用条件下检验系统的数据。

### 5. 方法

**抽帧**：视频按固定帧率采样，帧与 manifest 一同落盘，记录视频标识、帧号、时间戳与标签。

**有监督帧级分类**：在帧集上微调预训练分类网络。类别不平衡用平衡类别权重处理；选模使用留出验证集上的 **Macro-F1** 而非准确率——准确率会掩盖小类别的退化。

**时序建模**：帧级嵌入输入序列模型，使其在有时间上下文的情况下逐帧预测。同时实现循环头（GRU）与膨胀因果卷积头（TCN）；mean-pooling 头作为不含时序建模的对照。

**融合**：帧级与时序后验通过概率平滑、加权融合与多数投票组合——即 A3 的集成部分。

**意义建构**：融合后的标签流经平滑、按最小时长准则切分为连续动作片段，再依据 WHO 导出的规则评估：六步覆盖、重建序列中的顺序逆序、各步时长相对总搓洗时间平均份额的比例、以及总搓洗时长对照 40—60 秒建议。输出为结构化报告，并渲染为人类可读的摘要。

### 6. 评估与指标

我们报告准确率以便与已有工作对比，但绝不单独报告。**Macro-F1** 是主选模指标，因为它对类别不平衡不敏感。逐类 precision 与 recall 以及混淆矩阵用于定位**哪些**步骤被混淆——预期混淆为第 2 步与第 4 步、第 5 步与第 6 步。标签跳变次数直接度量单帧误判的减少程度，这是准确率无法表达的。同场景与跨场景 Macro-F1 量化域偏移。与人工真值在完整性与顺序上的一致率检验系统级主张。单段推理时间证明实际可用性，自助法置信区间确保所声称的提升不是采样噪声。

消融实验固定数据、划分、随机种子与骨干网络，只改变时序组件：(A) 纯帧级；(B) 帧级 + 概率平滑；(C) mean-pool 头；(D) GRU 或 TCN 头。这样是**隔离** A3 的贡献，而不是口头断言。
